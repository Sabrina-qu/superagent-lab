# Phase 2.3 投料清单（10 篇真实料）

> 用途：部署计划 6.4 步骤 3「用 10 篇真实料试跑 2 周」的投料登记与执行清单。
> 用法：老板逐行确认授权与来源后，按「二、每篇执行步骤」投料；数据回写 `docs/kb-trial-log.md`。

## 一、授权与来源前置（每篇都必须满足）

- [ ] 来源为老板自有或已获授权的内容（不得使用未授权的他人内容做试点）；
- [ ] 原始平台/账号/链接/抓取日期齐全，能写进原料 front-matter；
- [ ] 原料含**至少 3 条可逐字摘录的评论区内容**（门禁要求 Top3 热门梗；没有评论的料无法过门禁）；
- [ ] 不含老板私人信息、真实客户信息、未公开商业数据；
- [ ] 原料逐字落盘，worker 不得改写（门禁会比对逐字摘录）。

## 二、每篇执行步骤

1. 把原料存成 `kb-inbox/raw/<YYYYMMDD>-<平台>-<slug>.md`，按 `kb-inbox/raw/_template.md` 填 front-matter；
2. 用 `kb-intake` 模板发 issue（标题 `[kb] <料源> · <一句话主题>`，正文含 `@Sabrina-qu-bot`）；
3. superagent 建工单 → worker 产出 `org/skills/wanggan-cases/<同名>.md` 并提 PR；
4. 人工按 `kb-inbox/README.md` 第五节清单审 PR（重点：原料未改、`原句:` 逐字、枚举只取词表、门禁输出已贴）；
5. 合并 PR → 关闭 issue → 在 `docs/kb-trial-log.md` 记一行。

## 四、人工审阅清单（每 PR 逐条打勾）

- [ ] PR 只新增/修改 case 卡与必要沉淀，**原料文件零改动**（`git diff` 无 raw）
- [ ] 六个必填小节齐全非空；front-matter 必填字段齐全
- [ ] 枚举字段全部来自 `kb-inbox/vocabulary.yml`（无自造值）
- [ ] `原句:` 行逐字出现在原料中（无改写、无省略号拼接）
- [ ] 评论区 Top3 已填且为逐字原句
- [ ] PR 描述贴了 `python3 org/verify/check-kb.py <卡>` 完整输出与退出码
- [ ] 品味层（网感 rubric）评分：___ / 10，一条最重要的问题：__________

## 五、节奏

- 每天 1-2 篇，10 篇在两到三周内跑完；
- 每周三/日 15:00 按 `docs/kb-trial-log.md` 复盘：驳回原因分类、同类纠正 ≥3 次 → 转词表值或门禁检查项；
- 满 10 篇后按第六节判据决定是否进入 Phase 3。

## 六、Phase 2→3 判据（与试跑日志一致）

- [ ] worker 自跑门禁失败率连续两周 < 20%
- [ ] 人工纠正集中在 ≤3 类问题且都已固化硬规则
- [ ] 单篇人工 review ≤ 5 分钟
- 满足以上才扩到 2-3 条流水线。
