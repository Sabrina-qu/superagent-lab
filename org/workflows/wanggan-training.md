# 训练 SOP：IP 操盘手网感四阶段

> 总原则（照抄 Lauren）：先让坏网感"类别性不可能"（结构硬约束）→ 再静态检查（脚本发现违禁）→ 再 skills 引导 → 人工只做情报员。
> 进入循环前必须完成 **Week 0**：老板亲自定下 rubric 五项权重（见 `org/skills/wanggan-rubric.md` 权重表，只有老板能填）。

## Week 0：定宪法（老板亲自主导，约 2 小时）
- [ ] 填写 `org/skills/wanggan-rubric.md` 的权重表（五项权重和为 100%）
- [ ] 确认五项各自的 0 分/10 分锚点描述是否符合你的口味（可直接改）
- [ ] 指定 3 个对标账号 + 你账号的历史爆款清单（Week 1 的拆解样本来源）
- [ ] 指定训练主平台（抖音 / B站 / 小红书，平台腔指标按此校准）
- 产出：rubric 宪法 v1 生效，进入 Week 1。

## Week 1：模仿期——拆解爆款建库
- [ ] 拆解 50 篇爆款（老板选样本：历史爆款 + 3 个对标账号近期爆款）
- [ ] 每篇按 `org/skills/wanggan-cases/_template.md` 提取：钩子句式/情绪曲线/金句位置/CTA手法/评论区热门梗
- [ ] 每篇一个 case 文件进 `org/skills/wanggan-cases/`，文件名 `<日期>-<平台>-<账号>-<选题slug>.md`
- [ ] 跑一遍 `org/verify/check-wanggan.py` 对全部 case 的钩子段做硬指标统计，校准 rubric"平台腔"节的阈值
- 产出：《爆款结构库 v1》（= 内容版 feature map）；验收：case 数 ≥ 50。

## Week 2：仿写期——每日仿写 + 人工结构化评分
- [ ] 每天 5 篇选题仿写（content-lead 派单）
- [ ] 每篇先自跑 `org/verify/check-wanggan.py`，硬指标不过的直接重写，不交付
- [ ] 老板按 rubric 打分，**每篇 ≤ 2 分钟，只打分 + 写一条最重要的问题，不改写**
- [ ] 凡拿到 6 分以下项的稿子，回看 wanggan-cases 对应 case 对照重写
- [ ] 分数与批注进 `org/skills/scoring-log.md`（日期/选题/rubric 五项分/老板一条批注）
- 产出：仿写 ≥ 35 篇 + 评分记录 ≥ 35 条；验收：老板单篇评分时长 ≤ 2 分钟。

## Week 3：盲测期——防自证检验
- [ ] 同一选题：IP 操盘手仿写一稿 + 老板历史稿（或新写一稿），**打码关键信息后混合**
- [ ] 另一模型或可信第三人盲评：哪篇更有网感 + rubric 各成分分
- [ ] **纪律**：评委只见 neutral label，永远不知哪篇是谁写的；被测 bot 不知道自己在被测
- [ ] 达标线：bot 稿被选中率 > 60% 且 rubric 分差 < 1.5 → 进 Week 4；未达标回 Week 1/2 加训最弱成分
- 产出：盲测报告（选中率 + 各成分分差）。

## Week 4：对抗期——评论区模拟器 + 实测闭环
- [ ] 每个待发布稿先过 `org/skills/keyboard-xia.md` 键盘侠骂一轮，挑出的点处理完才进入终审
- [ ] 老板终审通过后用养号/小号灰度发布；一次发 2-3 条同选题变体，只动一个变量
- [ ] 24h/72h 数据回流，data-analyst 归因，结果回写 scoring-log 与案例库
- 产出：发布实测基线（回归系数）。

## 之后：每 4 周一轮迭代
盲测 → 对抗 → 数据回流 → 蒸馏（corrections 满 10 条 → rubric 修订提案，老板批准后生效）。

## 红线（全程有效）
1. 对外的稿永远经老板或老板信任的人手工终审；
2. 键盘侠攻击稿仅内部流转；
3. 梗库与案例库所有来源标注原账号；
4. 实验稿不打老板主身份，用养号/小号灰度；
5. rubric 宪法 bot 只能提议、不能自改（防自我放水退化）。

|---|---|---|---|---|---|
